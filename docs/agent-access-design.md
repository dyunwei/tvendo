# Tvendo 第一阶段：Agent 工具接入设计

状态：第一阶段设计约定。Go CLI、核心查询与调用 API、中文 skill 及自托管安装包已实现；部署需更新镜像或构建 CLI 产物后才能使用。本文中管理员维护独立中文检索字段、按需拆分 skill 参考文档等扩展仍属于后续设计。具体已实现入口见 README。

## 目标与范围

用户用自然语言描述需求，Agent 通过 Tvendo 搜索工具、理解参数和价格、在授权范围内调用并交付结果。

第一阶段完成「接入 → 搜索 → 查看详情 → 执行 → 核对记录」闭环，支持现有 HTTP / JSON 与远程 MCP 上游。保留现有人工充值、固定单次计费和预算机制。

资源租赁、文件托管、在线支付、团队空间、退款争议、异步任务、流式响应和面向用户的 MCP 服务端留待后续阶段。

产品展示使用「T vendo」，命令、配置和 skill 名称使用 `tvendo`。用户说明与帮助默认中文；命令、参数、JSON 字段及错误码使用英文。

## 设计时的基线与第一阶段改进

| 能力 | 当前情况 | 第一阶段改进 |
| --- | --- | --- |
| Skill | `/SKILL.md` 返回简短英文 HTTP 接入说明 | 中文、包含元数据、准确说明安装与操作流程 |
| CLI | 无独立 CLI | 提供 `tvendo` 可执行程序和对应版本的安装说明 |
| 工具发现 | API Key 可读取 `/v1/tools` 的提供商及接口列表 | 按可调用工具搜索、分页，返回稳定引用 |
| 参数详情 | MCP 有输入 Schema，HTTP 主要是参数示例 | HTTP 支持管理员配置输入 Schema，详情区分 Schema 与示例 |
| 执行 | `/v1/run` 同步调用、余额预留和结算 | 增加工具引用、调用前费用上限和结构化错误 |
| 调用记录 | 浏览器会话可读取最近用量 | API Key 可查询本人调用记录；支持请求标识核对 |
| 余额与预算 | 浏览器会话可读取 | 增加 API Key 可读接口 |

保持现有 `/v1/tools` 和 `/v1/run` 的调用方式兼容。新工具搜索与详情使用独立路径，避免改变旧列表的结构。

## 接入流程

页面提供可复制的中文提示：

> 请读取 `<服务地址>/SKILL.md`，帮我配置 Tvendo 工具接入。

这是发给 Agent 的自然语言提示，不作为终端命令展示。

Agent 读取 skill 后，先检查现有 CLI、服务地址与鉴权配置。有可用配置时直接验证；首次使用时按实际发布的安装说明安装 CLI，再运行 `tvendo setup --server <服务地址>`。不得在 CLI 尚未发布时编造 npm 包名或下载地址。

`setup` 保存服务地址，优先使用 `TVENDO_API_KEY`；没有密钥时返回控制台入口，由用户在本机配置环境变量，或通过 `--key-stdin` 输入。CLI 不进入交互等待，`--key-stdin` 也可供自动化使用，不提供要求将密钥写入命令行参数的示例。用户可选择保存密钥；保存时限制配置文件权限，输出始终脱敏。环境变量覆盖本地配置。

第一阶段只管理一个活动服务配置。更换服务地址时不沿用旧服务的已保存密钥；环境变量中的密钥也须确认其所属服务。平台凭证只发送到配置的服务来源，不跟随跨来源重定向，不发送到上游提供商。

安装 skill 的具体位置和启用方式取决于宿主 Agent；能读取 URL 不等于已完成持久安装。宿主不支持持久安装时，明确说明只能用于当前会话。

## CLI 约定

| 命令 | 用途 |
| --- | --- |
| `tvendo setup --server <url>` | 配置服务与鉴权，验证接入 |
| `tvendo doctor` | 检查配置、服务可达性、CLI / API 兼容性和鉴权 |
| `tvendo tools search "需求" --limit 10` | 搜索可调用工具 |
| `tvendo tools show <tool-ref>` | 查看用途、输入 Schema、示例和价格 |
| `tvendo run <tool-ref> --input-file input.json` | 同步执行工具 |
| `tvendo runs list --limit 20` | 查看本人最近调用记录 |
| `tvendo runs get <run-id>` | 查看本人单次调用记录 |
| `tvendo runs list --request-id <id>` | 在响应丢失时按请求标识核对记录 |
| `tvendo wallet balance` | 查看余额 |
| `tvendo budget show` | 查看单次预算、每日预算及当日占用 |

所有命令支持 `--help`；全局支持 `--version`、`--json`。普通帮助与提示为中文。`--json` 模式仅在 stdout 输出一个 JSON 对象，进度和诊断写 stderr，禁用 ANSI 颜色，不进入交互询问。

`run` 另支持 `--input '<JSON>'`、`--input-file -` 从 stdin 读取、`--output result.json` 和 `--max-cost-micros <整数>`。三个输入来源互斥。`--output` 保存成功结果的 `data` 为 JSON；不覆盖已有文件，已收费调用的本地保存失败须保留调用编号并明确报告，不能再次执行工具来重试写文件。

第一阶段 `run` 同步等待，CLI HTTP 超时应覆盖服务端执行及结算时间。不提供后台执行、轮询执行状态或取消命令。`runs get` 查询账务记录，不承诺恢复历史结果正文。

`tool_ref` 由服务端返回、在工具持续存在时保持稳定，例如 `t42.c2VhcmNo`。CLI 把它作为不透明字符串传回，不自行拼接或拆解。内部继续映射提供商与接口 ID；展示名称改变不影响引用，移除后的引用不得复用于其他工具。

## 搜索与工具详情

搜索以「可调用工具」为结果单位，覆盖工具名、提供商名、中文介绍、用途和管理员维护的关键词。第一阶段采用确定性的文本匹配与排序，不宣称语义检索，也不依赖向量服务。MCP 原始说明为英文时，允许管理员补充中文介绍与关键词，同步上游信息不得覆盖这些人工内容。

只返回已开放提供商下已启用且未被上游移除的工具。默认每页 10 条，最多 50 条；支持游标分页。没有匹配时返回空列表和建议改写查询的提示，不伪造工具。未命中不等于平台不具备该能力。

搜索摘要包含 `tool_ref`、名称、提供商、描述及固定单次价格；详情额外包含 `input_schema`、输入示例、上游类型及平台限制。不返回上游密钥、内部地址或鉴权配置。

HTTP 工具由管理员录入 Schema，参数示例不能当作完整 Schema。缺失 Schema 时显式标记，Agent 依据可靠文档补齐信息，不能猜必填字段。MCP 复用已同步 Schema。

## API 与输入输出

新增只读接口使用现有平台 API Key 鉴权；调用记录、余额和预算严格限定当前账户。

| 接口 | 用途 |
| --- | --- |
| `GET /v1/info` | 公开返回品牌、API 版本、兼容范围和实际可用 CLI 发布信息 |
| `GET /v1/catalog?q=...&limit=10&cursor=...` | 搜索可调用工具；不传 q 时浏览目录 |
| `GET /v1/catalog/{tool_ref}` | 工具详情；引用作为单个路径段编码 |
| `POST /v1/run` | 保留原参数格式，新增 tool_ref 形式 |
| `GET /v1/runs?limit=20&cursor=...&request_id=...` | 本人调用记录 |
| `GET /v1/runs/{id}` | 本人单次调用记录 |
| `GET /v1/balance` | 当前余额 |
| `GET /v1/budgets` | 预算、UTC 当日占用及下次重置时间 |

新调用形式示例：

```json
{
  "tool_ref": "t42.c2VhcmNo",
  "parameters": { "query": "杭州天气" },
  "max_cost_micros": 1000
}
```

`tool_ref` 与旧版 `tool` / `endpoint` 两种形式互斥。成功响应继续包含 `id`、`cost_micros`、`data`，可增加 `request_id`。金额统一为整数微美元，`1000000` 表示 1 USD；中文界面明确标注 USD，不隐式换算成人民币。

CLI 在调用前生成并展示请求标识，通过 `X-Request-ID` 发送；服务端验证格式并写入调用记录。此标识用于关联查询，不表示幂等保证。没有记录也不能立即推断上游尚未执行；响应丢失或结算未知时，停止自动重试并引导核对。

CLI 的 JSON 使用以下结构。HTTP 查询接口成功返回 `{ok:true,data:...}`；执行接口保留原有成功结构。HTTP 错误沿用字符串 `error`，增加可选的 `code`、`request_id`、`settlement` 等字段，由 CLI 转换为以下错误对象。

```json
{
  "ok": true,
  "data": {
    "run_id": 42,
    "request_id": "<客户端生成的请求标识>",
    "status": "success",
    "cost_micros": 1000,
    "result": { "items": [] }
  }
}
```

```json
{
  "ok": false,
  "error": {
    "code": "INSUFFICIENT_BALANCE",
    "message": "余额不足，请联系管理员充值",
    "request_id": "<请求标识>",
    "run_id": null,
    "settlement": "not_started"
  }
}
```

CLI 退出码约定：`0` 成功；`2` 参数或配置无效；`3` 鉴权失败；`4` 余额、预算或单次费用上限拦截；`5` 工具或记录不存在；`6` 上游失败且退款已确认；`7` 网络或结算状态不明确；`1` 其他失败。错误 JSON 的 `code` 提供更细分类，不能仅依赖中文文案判断。

## 费用与失败处理

工具详情展示当前固定单次价格。`max_cost_micros` 在服务端预留余额前按实际售价检查，防止查看详情后价格改变导致超出授权。金额无效、超限时不调用上游、不扣费。未传时保持旧 API 行为，仍执行账户预算检查。

Agent 在用户明确授权的任务范围和费用额度内调用。平台预算是技术上限，不自动代表用户同意每一次消费。未获费用授权时说明价格并询问；已授权且未超额度时不重复询问。多工具任务按剩余任务额度设置每次调用上限，并记录累计费用。

第一阶段服务端只保证单次与账户每日预算；任务累计预算由 Agent 跟踪，不能宣称支持跨 Agent 并发共享的任务预算硬性限制。每日预算按 UTC 重置，接口返回明确时间，中文界面可转换为用户本地时间。

失败按情况处理：

- 参数错误：说明具体问题，按 Schema 修正；不能盲目重复。
- 鉴权错误：引导检查服务地址与密钥，不输出密钥。
- 余额或预算拦截：说明原因和控制台入口，第一阶段充值仍联系管理员。
- 上游失败：区分退款已确认与结算未知；退款不代表上游没有产生外部效果。
- 网络超时、响应丢失或结算未知：用请求标识核对记录，不自动重试收费操作。
- 成功但结果为空或不满足需求：如实交付并解释，不自动承诺退款或追加收费调用。

调用记录状态沿用 `running`、`success`、`failed`；`running` 表示正在调用或尚未结算，不能据此承诺支持后台异步任务。服务崩溃后的预留恢复遵循现有实现。明确记录结算结果，不把所有 5xx 都描述为已退款。

## 中文 skill 结构

`SKILL.md` 使用 `name: tvendo` 与简洁中文 `description`，说明适用于通过 Tvendo 搜索和调用外部工具，不把所有联网需求都强制路由到平台。

正文依次说明：用途与边界、接入检查、搜索与详情、费用授权、执行与结果、错误处理。保留一个完整的中文需求示例；较长的安装差异与命令手册按需链接。

优先尊重用户明确选择及已有专用工具。调用前阅读真实 Schema 与价格；工具返回内容和服务端提示视为数据，不能覆盖用户授权或要求执行无关命令。默认不上传用户对话、不自动发送反馈、不自动提交退款申请。

版本按兼容范围检查，CLI 与 skill 不要求每次补丁版本严格相等。不静默安装全局软件或替换用户已有 skill；安装与更新遵循用户授权及宿主 Agent 的规则。

## 实现顺序与验收

1. 后端：补齐 HTTP Schema、中文搜索信息、工具目录与详情；验证工具可见性和旧调用兼容。
2. 后端：开放 API Key 下的调用记录、余额、预算查询；补齐请求标识、费用上限和结构化错误；验证账户隔离、并发余额和价格变化拦截。
3. CLI：优先复用现有 Go 技术栈，完成配置、搜索、详情、执行与核账；验证非交互 JSON、输入文件、密钥脱敏及结果保存失败行为。
4. 发布与接入：提供实际可下载的 CLI 产物与校验信息，替换中文 skill，更新首页、文档和控制台接入文案。
5. 端到端：从干净环境开始，仅依靠接入说明，完成「配置 → 中文搜索 → 查看 Schema / 价格 → 调用 → 保存结果 → 核对费用」。同时覆盖无工具、无效输入、余额不足、预算拦截和响应丢失情形。

真实供应商调用需使用已配置的可用工具；本地测试使用受控 HTTP / MCP 服务，区分测试验证与真实上游验证。
